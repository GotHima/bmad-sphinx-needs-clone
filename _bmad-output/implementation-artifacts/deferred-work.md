## Deferred from: code review of 1-2-initialize-sqlite-database-layer (2026-07-25)

- **`need.status` not FK'd to `status_value`** (`lib/db.ts:41`) — Architecture design choice: status stored by value string, not by FK to `status_value.id`. Stale status strings possible if status values are deleted. Enforce at application layer in future stories (e.g., Story 2.2 deleteStatus guard, Story 3 createNeed/updateNeed validation).
- **No WAL mode / busy_timeout pragmas** (`lib/db.ts:23`) — `db.pragma('journal_mode = WAL')` and `db.pragma('busy_timeout = 5000')` would harden against SQLITE_BUSY during HMR or parallel builds. Not required by spec (local single-user tool, NFR-3).
- **No error handling on `mkdirSync` + partial DB init** (`lib/db.ts:9,21`) — Permissions errors produce raw Node.js stack traces. Unclosed DB handle on `db.exec()` throw. Acceptable for local dev tool; add user-friendly diagnostics if containerized or CI use is added.
- **DDL not in explicit transaction** (`lib/db.ts:27`) — `db.exec()` runs each `CREATE TABLE` as individual auto-commits. Partial schema on crash is self-healing via `CREATE TABLE IF NOT EXISTS` on next startup (AD-8).
- **No index on `need_link.to_id`** (`lib/db.ts:52`) — Backlink query `SELECT from_id FROM need_link WHERE to_id = ?` is a full table scan. Add `CREATE INDEX IF NOT EXISTS idx_need_link_to_id ON need_link(to_id)` when row count warrants it (NFR-2: ≤500 rows in MVP).
- **`created_at`/`updated_at` have no DEFAULT values** (`lib/db.ts:47-48`) — Server Actions must always supply both values. Add `DEFAULT (strftime('%Y-%m-%dT%H:%M:%fZ', 'now'))` on `created_at` and a trigger on `updated_at` as a convenience enhancement.

## Deferred from: code review of 3-2-create-need-via-side-sheet (2026-07-28)

- **Concurrent multi-user ID suggestion collision** (`lib/actions/needs.ts:18-23`) — `suggestNeedId` reads `MAX(seq)` without isolation; two sessions opening simultaneously receive the same suggestion and the second create attempt hits the UNIQUE constraint. Single-user local SQLite tool; UNIQUE constraint ensures correctness on save. Harden if multi-user is added.
- **Type-not-found error swallowed as generic failure** (`lib/actions/needs.ts:44,83`) — `throw new Error('Type not found')` inside the transaction is caught and returned as `'Failed to create need'`. - **`NewNeedButton` has no internal `<Suspense>` self-guard** (`components/layout/NewNeedButton.tsx:1`) — The component calls `useSearchParams()` which requires a `<Suspense>` boundary. Currently wrapped correctly in `AppTopBar`. If the component is reused elsewhere without a boundary, the page will throw at runtime with no compile-time warning. Add JSDoc comment or consider wrapping internally if reused.
- **`revalidatePath('/')` only invalidates home route** (`lib/actions/needs.ts:77`) — Future routes that display needs (e.g. `/needs/[id]`, filtered views) will remain stale after `createNeed`. Switch to `revalidateTag` keyed to needs data, or add additional `revalidatePath` calls, when new routes are added.

## Deferred from: code review of 5-1-filter-bar-with-url-state-and-server-side-filtered-query (2026-08-05)

- **SQL LIKE metacharacter leakage in tags filter** (`lib/queries/needs.ts:43-44`) — Tags containing `%` or `_` are passed as-is into `n.tags LIKE ?` patterns, so a tag `"50%"` becomes `LIKE '%50%%'` and matches more broadly than intended. Fix with a helper that escapes `%` → `\%` and `_` → `\_` in tag values before wrapping with `%`. Add `ESCAPE '\'` clause to the LIKE expression.
- **Comma in tag value splits on URL round-trip** (`FilterBar.tsx:104`) — A tag value containing a comma (e.g. `"a,b"`) is stored via URLSearchParams (encodes comma as `%2C`) and then decoded back to `"a,b"`, which `parseCommaParam` splits into two separate filter tokens. Fix by replacing comma-joining with a different delimiter (e.g. `|`) or by percent-encoding commas before joining in `pushParams`.
